## Т1. Календарь и расписание: даты, архив, дублирование недель `[x]` (коммит cac0491; per-date штамповка, единый формат, честные пустые состояния, календарь преподавателей; тесты 139/0)

**Баг заказчика:** при выборе даты прошлой недели (тот же день недели) показывается расписание текущей недели; прошлые расписания не сохраняются корректно. То же в календаре преподавателей.

**Диагноз (подтверждён исследованием кода):**
1. Источник: при синхронизации ВЕСЬ недельный документ штампуется ОДНОЙ датой запроса — `MpkNetworkClient.kt:82,132,159` → `MpkScheduleParser` (`:502, 859, 992, 1023, 1092, 1157, 1175`). Реальных по-дневных дат в БД нет; за N дней копятся N копий недели с неверными подписями.
2. Студенческий календарь: выбор даты даёт ISO `yyyy-MM-dd`, БД хранит `дд.ММ.гггг` → точное сравнение не срабатывает никогда (`CalendarArchiveDialog.kt:125-128`), и всегда включается фолбэк `filter { it.dayOfWeek == dow }` (`:143`) → «текущая неделя» на любую прошлую дату.
3. `ScheduleScreen.selectedDateString` мёртв (присваививается только `""`, `ScheduleScreen.kt:173,350,363`); `CalendarArchiveDialog` вызывается без `onDateSelected` (`:269-273`). Панель дней читает `getLessonsForDay` (чистый dayOfWeek, `LessonDao.kt:14-15`) и дедуплицирует «максимальной датой» лексикографически (`ScheduleScreen.kt:212-215`) — день важнее месяца, баг «28.09 > 05.10».
4. Календарь преподавателя: `SimpleDateFormat("dd.MM.yyyy").parse(dateStr.replace("-","."))` бросает ParseException → выбор даты молча теряется (`CollegeScreen.kt:1387-1399`); времена уроков всегда по понедельнику `getBellsForDay(1)` (`:1536-1537`); парсер `TeacherScheduleParser.kt:51-86` вообще не имеет размерности дня недели (все дни сливаются в один список 1..10); файл преподавателей качается по точной дате (`MpkNetworkClient.kt:250-272`) — прошлые дни 404.
5. Формат дат: закрепить `дд.ММ.гггг` как единственный формат хранения (решение уже принято в CODE-AUDIT 8.3); все сравнения нормализовать в одну форму.
