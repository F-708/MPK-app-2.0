## 1. Резюме решений консилиума

1. **Форма поставки: build flavor `teacher` в текущем проекте** (`applicationIdSuffix=".teacher"`, отдельный APK, общий код). Единогласно отвергнуты: форк кодовой базы (×2 поддержка навсегда), режим «я преподаватель» внутри ученического приложения (виджеты group-driven, требование «спрятать ученическое совсем», желание заказчика), PWA (требует сервера — красная линия; нет виджетов/пушей).
2. **Сроки: демо 2–2.5 рабочих дня, релиз-кандидат 8–10 рабочих дней + 2 календарных дня 48-часового теста виджетов** (оценка критика-2, принятая вместо заниженной оценки архитектора).
3. **Первый коммит — НЕ flavor, а фикс бага однофамильцев (surnameKey) в общем main-коде**: он уже сегодня ломает живое ученическое приложение (Савицкая ×2, Ерёменко ×2 сливаются в одну карточку) [VERIFIED: TeacherLessonDao.kt:13-23, CollegeScreen.kt:1514].
4. **Четыре жёстких условия запуска** (без них не ship'им): surnameKey-фикс до flavor-работ; privacy-разделение (§7); `TeacherScheduleWorker` в MVP (иначе кэш вечно вчерашний); контракт честности (§4.2).
5. **Честная граница продукта**: «виджет, который никогда не соврёт про замены», в v1 недостижим в принципе (замены живут в Viber-чатах, машинного канала нет). Достижим контракт: «приложение врёт только если я сам его не покормил» (override + метки свежести + молчание вместо вранья).

## 2. Цель, аудитория, критерии успеха

**Цель**: дать преподавателю МГПК (~100 человек) его рабочий день одним экраном и на lock-screen — быстрее и надёжнее, чем .doc с сайта в маршрутке и фото бумажки с кафедры.

**Аудитория** (две персоны консилиума, обе сошлись в главном):
- «Ирина Николаевна», 54: специальные дисциплины + классное руководство 41О, закреплённый кабинет, Samsung A24. Нужно ОДНО: «что у меня сегодня и где», кабинет самым крупным шрифтом, никаких регистраций, офлайн (во 2-м корпусе одна палка сети). Демография не прощает багов: глючит → удалила → не поставит.
- «Артём», 26: 6-8 групп, 18-24 пары/неделю, кабинетная система, 4 кабинета в 2 корпусах за день, совместитель. 80% ценности — lock-screen виджет «следующая пара: время • группа • кабинет» за 8 секунд без тапов. Виджет соврал один раз — мёртв навсегда.

**Критерии успеха v1** (продуктовая бумага 01):
- 45–60 установок из ~100 за 3 месяца при сценарии «завуч → педсовет → install-party»; без завуча реалистично 15–20;
- WAU/MAU ≥ 0.5; виджет стоит у ≥40% установивших;
- ≥1 кейс/мес реальной ценности (в т.ч. для администрации);
- ноль инцидентов «приложение уверенно соврало без метки свежести».

**Метрики без телеметрии** (красная линия): счётчик загрузок через QR/APK-рассылку + личные интервью. Аналитику НЕ заводим.

## 3. Форма поставки: flavor `teacher` (архитектура)

### 3.1 Конфигурация сборки
```
flavorDimensions += "version"        // уже есть
create("teacher") {
    applicationIdSuffix = ".teacher"
    versionNameSuffix = "-teacher"
}
src/teacher/res        — иконка (отличающаяся радикально, см. §12), app_name, строки
src/teacher/assets     — teachers_contacts.csv (§7)
src/teacher/java       — TeacherRoot/NavHost, teacher-экраны (минимум)
```
- Прецедент admin-flavor живой и проверенный [VERIFIED: app/build.gradle.kts:18-27].
- **Правило разработки (жёсткое): ноль `BuildConfig.FLAVOR` в общем коде, кроме одной точки ветвления в MainActivity** (сегодня у admin ровно 2 гейта). Общие экраны принимают параметры (`teacherMode`, профиль из prefs) → вся логика покрывается standard-прогоном тестов (тест-пробел: 784 теста гоняются только на standardDebug; CI тесты не гоняет вообще [VERIFIED: build-apk.yml]).
- Компиляция standard+teacher после каждой волны. Релиз «паровозом»: общий versionCode, одновременная выкладка при общем фиксе парсера — иначе два приложения на одной кафедре врут по-разному.

### 3.2 Источник данных
- **Отдельный документ преподавателей** `…-raspisanie-prepodavatelej.doc` на guo-mpk.by (существует и парсится общим кодом [VERIFIED: MpkNetworkClient.kt:353, слаги ""/-2, гейт даты в шапке]) — teacher-сборке тяжёлый групповой док в v1 не нужен вовсе.
- Цепочка «док → парсинг → кэш `teacher_lessons` (Room) → UI сегодня/завтра/календарь» УЖЕ существует и покрыта 7 тест-файлами [VERIFIED: MpkNetworkClient:353-387, ScheduleRepository:577-610, CollegeScreen:1468-1730].
- **Дыра**: текущий `ScheduleCheckWorker` НЕ заполняет `teacher_lessons` [VERIFIED: ScheduleCheckWorker:76 → syncScheduleForDate:503-535] и молчит вне окна 10:00–21:00 [VERIFIED: ScheduleCheckWorker.kt:30-32]. Отсюда — новый воркер и утренний прогон (§5.3).

### 3.3 База данных
- Room общая на все flavor'ы, `fallbackToDestructiveMigration` включён сознательно → **любая новая таблица только с явной миграцией + Robolectric-тестом**.
- v1: **одна новая таблица `teacher_overrides`** (локальные правки/замены, §5.4) + `MIGRATION_9_10` + `MigrationV9ToV10Test`. Забытая миграция тихо стирает `student_tasks` учеников — недопустимо.
- Профиль преподавателя («кто я») — SharedPreferences (не Room). Нагрузка — вычисляемое из кэша (не храним).

### 3.4 Фикс surnameKey (волна 0, общий код)
- Баг: выборка `teacher_lessons` фильтруется только по `surnameKey` (голая фамилия) → однофамильцы сливаются. Единственный call-site CollegeScreen:1514 → фикс в одном пути чинит ОБА приложения.
- Фикс: фильтр `TeacherInsights.matchTeacher(row.teacherName) == selected` при чтении (миграция не нужна: teacherName хранит сырое «Фамилия И.О.»).
- **Обязательная ветка неоднозначности**: `matchTeacher` возвращает null на голой фамилии [VERIFIED: TeacherInsights.kt:136] → при коллизии и недостатке данных показываем плашку «Не удалось точно определить (две Савицкие) — проверьте список» + обе строки. Тихая догадка и молчаливый дроп ЗАПРЕЩЕНЫ.
- **Сплит `teacherRows` по «/» (3 строки)**: ячейка «Иванов/Петров» в доке сейчас видна только первому — без сплита тест-фикстура ниже падает.
- Тесты-фикстуры: «Савицкая С.И. / Савицкая Н.П.», голая фамилия, сплит «Иванов/Петров».

### 4.2 Долг чести v1 (обязательства, без которых релиз не готов)

1. **Контракт честности** — продуктовый закон teacher-сборки:
   (а) timestamp «обновлено в HH:MM» на экране дня + утренняя плашка свежести на карточке текущей/следующей пары («по данным на вчерашний вечер — сверьтесь с чатом учебной части»);
   (б) личный override с полевым diff-сбросом и уведомлением о сбросе;
   (в) онбординг-договор дословно: «Приложение знает ваше расписание с сайта колледжа. Замены из чата учебной части в нём не появятся — пометьте их одной кнопкой, и виджет покажет правильно.»;
   (г) утренняя сводка с action «Пометить»;
   (д) **никогда не врать молча** — включая право промолчать вместо врущего пуша.
2. surnameKey-плашка неоднозначности (§3.4).
3. Метки свежести везде: экран дня, виджет (последнее известное + «обновлено в», НЕ пустота/спиннер), текст сводки, экран группы v1.1.
4. `MIGRATION_9_10` + `MigrationV9ToV10Test` (Robolectric, реальная БД).
5. CI-гейт: `testStandardDebugUnitTest` в build-apk.yml (волна 0); `testTeacherDebugUnitTest` — в релиз-чеклист.
6. Ноль `BuildConfig.FLAVOR` в новом teacher-коде (параметры вместо гейтов).
7. Релиз паровозом: общий versionCode standard+teacher при общих фиксах парсера.
8. LiveDocTest/живой curl на guo-mpk.by зелёный В ДЕНЬ рассылки — иначе не рассылаем.
9. Промер фактического времени публикации дока преподавателей 5–7 вечеров (curl) ДО фиксации таймингов §5.3 [ASSUMPTION: окно публикации не измерено никем].
10. `dexdump teacher-release.apk | grep StudentsRepository` + unzip-гейты — R8-вырезание не проверять верой.
11. versionName в «О программе»; файл `mpk-teacher-x.y.apk` (автообновления нет — v1.1).

### 4.5 УБИТО (запрет, не «отложено»)
| Что | Почему |
|---|---|
| Форк кодовой базы | ×2 навсегда на парсере/миграциях/CI; единственный полный консенсус всех бумаг |
| Режим «я преподаватель» в ученическом | Требование заказчика + group-driven виджеты + «спрятать ученическое»; экономия ~1 дня не стоит обратной миграции |
| Журнал посещаемости и оценки студентов | **Запрет навсегда**: ПДн несовершеннолетних, дубль официального журнала, одна потерянная БД = конец доверия администрации |
| Дни рождения студентов | ПДн несовершеннолетних |
| Аккаунты / регистрация / PIN | Красная линия обеих персон; идентификация = юр-периметр + отвал 50+ на первом экране |
| Телеметрия / аналитика / crash-репорты с user-id | «Приложение за мной следит» = скандал в учительской; при N=100 аналитика дороже инсайта |
| Геолокация | Статическая карта; запрос геолокации у 55-летней = удаление |
| Чаты, объявления, новости, поздравления, rate-app | «Второй чат — это два чата, в одном из которых никто не читает» |
| Реклама, платные функции | «Мы бюджетники» — удаление без разговоров |
| PWA | Требует хостинга (= сервер, красная линия скептика); нет виджета/пушей |
| Wear OS | Часов нет ни у кого |
| Напоминание о каждой паре | 4-6 пушей/день = канал отключат вместе с полезными |
| Динамические звонки / сокращённые дни | YAGNI; вместо — честный текст «по стандартному расписанию» |
| Полный редактор расписания (перенос на другой день), история правок с экспортом | Усложнение слияния с синком ради редкого сценария |
| Виджет звонков, виджет недели | Плотность выше порога читаемости home screen |
| Отдельная вкладка «Группы» (40 групп) | Переход «из контекста моей пары» естественнее |
| Два одноимённых teachers.csv (main+flavor) | Рассинхрон каталога при первом обновлении гарантирован |
| Фото-заглушки вместо переноса teachers_photos | Гейт должен проверять отсутствие, а не подмену |

## 5. Данные, синхронизация, уведомления

### 5.1 Профиль («кто я»)
SharedPreferences: surnameKey + полное ФИО из teachers.csv. Смена — из TopBar. При коллизии однофамильцев онбординг показывает ОБЕ карточки (должность/предметы/кабинет) — пользователь выбирает себя сам, приложение не угадывает.

### 5.2 Чтение расписания
`teacher_lessons` (существует) + оверлей `teacher_overrides` (§5.4) при каждом чтении. Фильтр по matchTeacher (§3.4). «Мой день» = строки teacher_lessons на dateString, отсортированные по lessonNumber, с применёнными override и статусами ИДЁТ/СЛЕДУЮЩАЯ/ПРОШЛА по Calendar (конвенция проекта: только Calendar, dd.MM.yyyy).

| 06:30–06:45 | `TeacherScheduleWorker`: одноразовый sync сегодня+следующий учебный день, force=true для сегодня | Явное исключение из окна 10–21 (подготовка сводки, не периодическая проверка); NetworkType.CONNECTED; при неудаче — повтор на 15-мин тиках до 07:15 |

Дока свежее нет → «Сегодня по расписанию с сайта от вчера 21:40 — возможны изменения, сверьтесь с чатом учебной части». Кэш на сегодня пуст → НЕ отправляем вовсе. Action «Пометить изменение» → override-лист. Настройка времени 07:00–08:00 |
| за 10 мин до пары | `lesson_reminder` | Только смена кабинета ИЛИ первая пара дня; настройка 5/10/20 |

**До релиза обязательно**: промер времени публикации дока преподавателей curl'ом 5–7 вечеров подряд — без него все тайминги выше [ASSUMPTION].

### 5.4 Override-замены (локальные правки поверх синка)

Таблица `teacher_overrides` (Room v9→v10):
```
id, dateString, lessonNumber,
kind: OTHER_ROOM | NO_LESSON | SOMEONE_ELSE,
room (nullable), note (nullable, для v1.1 «заметка к паре»),
createdAt, expiresAt (конец дня)
```
- UI: кнопка «Править» на карточке пары (hit ≥48dp) → bottom sheet, три варианта одним списком. Маркер ✎ «ваша правка». «Отменить правку».
- Потребители override: экран дня, виджет, напоминания, статус ИДЁТ. Правка личная и НИКОГДА не влияет на ученическое приложение (два слоя, пользователь предупреждён онбордингом).
- **Полевой diff-сброс (жёсткое условие)**: правка сбрасывается ТОЛЬКО если конкретное поле конкретной пары (room/time/groups/факт наличия) изменилось в новом доке. Сравнение по ключу (dateString, lessonNumber) до и после `replaceForDate` (который перезаписывает ВЕСЬ день [VERIFIED] — наивный «док новее → сбросить» собственноручно вернёт неверный кабинет в виджет).
- **Уведомление о сбросе — всегда**: «Расписание обновлено: ваша правка на вт, 3-я пара сброшена — в доке теперь 241». Молчаливый сброс запрещён.
- Автоистечение в полночь; вход в override одной кнопкой из уведомления (action «Пометить»).
- Вне v1 (честно говорим в онбординге): «меня поставили на замену в чужую группу» (новой пары нет в доке) — требует форму ввода = красная линия «v1 read-only».
- Отклонено: перенос пары на другой день, изменение времени, история правок с экспортом.

## 6. UX-спецификация

### 6.1 IA и навигация
- **3 вкладки: Сегодня / Неделя / Ещё.** Свайп между вкладками (механика v2.5). Системный back с корня — выход.
- «Ещё»: Звонки (только сетка), Карта колледжа (as-is из v2.5), Расписание группы (v1.1), Настройки (профиль, уведомления 5/10/20 мин + время сводки, виджеты, OEM-справка, «О программе» + дисклеймер).
- TopBar: ФИО (тап → смена профиля), кнопка синка (pull-to-refresh тоже), метка свежести.

### 6.2 Онбординг (первые 60 секунд — решают всё)
1. Приветствие + договор (текст контракта честности §4.2в) — 1 экран.
2. Поиск себя по ФИО (существующие TeachersPage+FuzzySearch), карточка-подтверждение (ФИО, должность, предметы, кабинет). Однофамильцы → обе карточки.
3. Мягкий pre-prompt уведомлений («уведомлять об изменениях расписания?») — ПОСЛЕ показа расписания, никогда до.
4. Чип «добавьте виджет» с инструкцией.
Никаких разрешений до расписания. Никаких пустых экранов. «Пропустить» на каждом шаге.

### 6.3 Экран «Мой день»
Карточка пары: время (крупно), предмет, группа(ы) чипами (тап → «мои пары у группы»), кабинет КРУПНЕЙШИМ шрифтом + чип-кнопка маршрута (⚑ ≥48dp), статус текстом+цветом (ИДЁТ / СЛЕДУЮЩАЯ / ПРОШЛА), маркер ✎ «ваша правка» при override, кнопка «Править». Сегмент Сегодня/Завтра (после 20:00 на «Завтра» бейдж свежести). Автопрокрутка к текущей/следующей. Пусто: «Сегодня пар нет. Следующая — вт 09:50, 241» / «Выходной» / «Каникулы до 01.09».

### 6.4 Экран «Неделя»
Полоса дат Пн–Сб с бейджами числа пар → карточки выбранного дня (тот же компонент). Блок «Нагрузка»: пар за неделю, часы по группам/предметам за видимый период (месяц в пределах 60-дневного кэша), inline-дисклеймер НА САМОЙ ЦИФРЕ. Синк недели: 6 доков, честное состояние «3 дня из 6 скачались».

### 6.5 Виджеты
- «Следующая пара» 4×1 и 2×2: время • группа • кабинет КРУПНО + «обновлено в HH:MM»; тап → экран дня; long-press-кнопка маршрута (v1.1 авто-строка маршрута).
- «Моё сегодня» 4×2: список пар дня со статусами, как TodayScheduleWidget, но teacher-driven.
- Пустые состояния осмысленные («Сегодня пар нет» + следующая пара), колокольчик-AVD сохранён.
- Кэш-ключ ОБЯЗАН включать: дату, минуту, профиль, pref-ы (грабли v2.x: кэш-ключ без даты = виджет «отключается через день»).
- OEM: 48ч тест Xiaomi+Samsung до релиза; first-run справка autostart/battery.

### 6.6 Доступность 50+
Hit-зоны ≥48dp, ChipText ≥13sp, body ≥16sp — через teacher-обёртку темы (composition-local), Tokens.kt не трогаем. Статусы — текст+цвет. Контраст ≥4.5. Минимум жестов (свайп вкладок опционален — тумблер существует в v2.5).
