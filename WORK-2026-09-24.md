## Разбор (по факту кода, а не по симптомам)

### Б1. Уведомление говорит «пары», а система — уроки `[ГОТОВО]`
`util/NotificationHelper.kt:68-72` — формы слова «пара».
Заказчик: 8 уроков в расписании → «8 пар». Заменить на «уроки».
Сделано: «урок/урока/уроков» по правилам русского.
Бонус по пути: `dayTitle` считался в воркере и передавался, но в заголовке не
использовался — всегда «Занятия на завтра». Но у 2+ курсов в пятницу цель — понедельник
(`ScheduleCheckWorker.kt:55`), и уведомление врало про день. Теперь «Занятия в среду: N уроков».

### Б2. Доля секунды при переключении «Сегодня/Завтра» `[ГОТОВО]`
Разведка: данные **не** перекачиваются. Один Flow по группе (`ScheduleScreen.kt:269-285`),
сеть при переключении не идёт. Задержка = кроссфейд `AnimatedContent` (`:522-530`):
дефолтные 220 мс на вход + 220 на уход; контент приходит на ~90 мс позже, полная
замена — ~220 мс. Читается как «нажал — через долю секунды открылось».
Сделано: `fadeIn(tween(110)) togetherWith fadeOut(tween(90))` — сохранена мягкость без лага.

### Б3. Расписание качается заново при VPN без доступа к сайту `[КОРЕНЬ, ОТКРЫТО]`
Разведка подтвердила жалобу: **дискового кэша нет вообще**. `MpkNetworkClient.downloadFileBytes`
читает ответ в `ByteArray` в heap и выбрасывает (`MpkNetworkClient.kt:240-248`);
OkHttp собран без `.cache(...)` → HTTP-кэш отключён. Единственный «кэш» — счётчик строк в Room.
Doc-файл никогда не сохраняется и не удаляется — его просто негде хранить.

Куда ходит повторно (все — без гейта, `force=true`):
| Триггер | Файл |
|---|---|
| Кнопка синка в шапке / пустое состояние | `ScheduleScreen.kt:437`, `:617` |
| Смена группы | `AppViewModel.kt:132` |
| «ОБНОВИТЬ» в чужой группе | `GroupScheduleScreen.kt:547` |
| Открытие чужой группы | `GroupScheduleScreen.kt:164-167` |
| Диалог кабинета на карте | `CollegeMapScreen.kt:197-209` |
| Воркер каждые 15 мин | `ScheduleCheckWorker.kt:82-83` — при «расписание ещё не опубликовано» pref-флаг не ставится (`:122`) → долбит сайт бесконечно |

Цель заказчика: скачал doc → распарсил **все** группы и **все** преподаватели → сохранил
в Room → doc удалил. Тогда «завтра», чужая группа, преподаватель и кабинет — офлайн и мгновенно.

### Б8. Виджет → скролл к текущему уроку + одноразовая подсветка `[ОТКРЫТО]`
Механизм уже есть: `EXTRA_SCROLL_TARGET="CURRENT_LESSON"` → `MainScreen.kt:193` →
`ScheduleScreen.kt:361-373` + холодный старт `:342-355`. Не хватает:
одноразовой подсветки-«волны» на текущем уроке при входе через виджет.
Правила заказчика: уроки идут → текущий по центру (или вниз, если последний);
уроки кончились → начало списка **на завтра**; звонки — как есть (уже правильно).
По пути найдено: `EXTRA_DAY_OF_WEEK` и `EXTRA_TARGET_DATE` из уведомления
(`NotificationHelper.kt:57-58`) **не читаются нигде** — мёртвый груз.

### Б13. Архитектурная оптимизация `[ОТКРЫТО]`
Общий принцип: не наслаивать, не перерисовывать, не перезапрашивать. Точечно:
- `TeachersRepository.loadTeachers()` перечитывает и парсит `teachers.csv` из ассетов
  **при каждой рекомпозиции-реминдере** в 6 местах (`ScheduleScreen.kt:100`,
  `GroupScheduleScreen.kt:170`, `CollegeScreen.kt:165/223/247`, `StudentsScreens.kt:436`).
  В `ScheduleScreen` уже есть процессный синглтон-кэш (`:96`) — распространить тот же приём.
- `WidgetData.todayLessons` использует `runBlocking` (`NowNextWidgetProvider.kt:156`).
- `LessonDao`: индексов нет вообще — все запросы по `groupName`/`roomFirst`/`roomSecond`
  идут full scan; нет запроса по преподавателю.
- Две разные «дата завтра»: `ScheduleRepository.nextSchoolDay:209` (пт → сб)
  против `MpkNetworkClient.calculateTargetCalendar:228-238` (пт ≥15:00 → пн).
  Гейт кэша и то, что качается, расходятся в пятницу вечером/субботу.
- `AppUiState.hasSyncError` (`AppViewModel.kt:42`) выставляется и не читается в UI.
- Нет in-flight дедупликации: VM-синк и локальный `syncForeignSchedule` имеют
  каждый свой `isSyncing` → параллельные загрузки одного doc.
