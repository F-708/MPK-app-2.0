# Полное ревью MPK app — сводка (2026-10-01)

> Единая точка входа. Детали — в отчётах 01–09 этого каталога. План работ — `MPK-app-2.1/REVIEW-PLAN.md` (волны A–F).
> Ревью провели: босс лично (01, 03*, 04, 05, 07, 08, 09), субагенты (02, 06). *03 — агент оборван, босс дописал с честными confidence-метками гипотез.

## Вердикт по проекту

Код работает, но держится на точечных латках (шифры T/O/Б/F/W/C в комментариях — история заплат). Архитектурного фундамента нет: нет DI, нет Navigation-компонента, god-экраны по 1300-1900 строк, состояние дублируется между экранами и VM самодельными паттернами. Все 5 жалоб заказчика имеют конкретные root cause, три из них доказаны живыми данными (curl/CSV-проверки). Хорошая новость: критичные фиксы дешёвые (URL-резолвер, нормализация прочерка, hit-test карты), а системные проблемы (навигация, DI) решаются двумя выделенными волнами без переписывания всего.

## ТОП-подтверждённые критичные баги

1. **SCH-01** — синхронизация расписания не попадает в реальные URL сайта. ДОКАЗАНО curl 2026-10-01: документ на сегодня лежит в `/uploads/2026/09/01.10.2026-raspisanie-uchashhihsya-1.doc` (месяц загрузки + суффикс коллизии + спрятан в iframe event-страницы), код пробует только `/uploads/2026/10/...` без суффикса → 404. Половина решения уже написана и не подключена (`extractDocumentUrls` умеет iframe; `generateCandidateEventUrls` — мёртвый код). Фикс: ScheduleUrlResolver. → Волна A1.
2. **WID-01** — виджет «СЕГОДНЯ» показывает последнюю дату в БД, а не сегодня (`todayLessons`, NowNextWidgetProvider:204-211). При провале синка (SCH-01!) пользователь видит расписание ПРОШЛОЙ недели под заголовком «СЕГОДНЯ». → Волна A2.
3. **TEA-01** — прочерки контактов: в `teachers.csv` в 89/100 строк в room/phone/email буквально «—» (U+2014), `isNotBlank()` их пропускает, секция «Контакты» рисуется всегда. Фикс: нормализация «—»→"" в парсере (6 строк), UI заработает сам. → Волна B1.
4. **TEA-02** — строки 48, 93 teachers.csv имеют 11 полей вместо 10 (лишняя `;`) → колонки съезжают, стаж/категория = мусор. ПОДТВЕРЖДЕНО awk. → Волна B2.
5. **ARC-03** — `StudentsScreens.kt:88`: блокирующее чтение 800 КБ students.csv на main-thread внутри `remember{}` → ANR на admin-сборке. → Волна E2.
6. **SUI-01** — «сегодня» в UI расписания залипает: `remember{Calendar.getInstance()}` без ключа (ScheduleScreen:147,204, GroupScheduleScreen:179,198, +2 диалога). Открыл приложение после полуночи — показываешь вчерашний день. → Волна A/B (дёшево).
7. **WID-02/BEL-02** — обновления виджетов/отсчёта стоят на exact-alarm, который на Android 14+ не выдан по умолчанию → inexact-будильник с задержками до 15 мин в doze; + FGS убивается OEM без watchdog. → Волна C.
8. **DAT-01** — у таблицы `lessons` нет индексов: тысячи строк (кэш всех групп), виджет сканирует её каждую минуту. Нужна MIGRATION_2_3 + тест. → Волна D1.

## Кросс-доменные паттерны (чинить одним движением)

1. **`remember{Calendar.getInstance()}` без ключа дня** — минимум 6 мест (ScheduleScreen×2, GroupScheduleScreen×2, CollegeMapScreen×2, диалоги). Один фикс-паттерн: ключ = день года, или обновление по lifecycle-событию ON_RESUME.
2. **dow-конверсия Calendar→1..7 продублирована 18 раз в 12 файлах**, при том что `MpkScheduleParser.dowOfCalendar` уже существует. Механическая замена (волна E3).
3. **ScheduleRepository создаётся в 6 местах с разным набором deps** (где-то teacherLessonDao=null — офлайн-преподаватели тихо не работают). Единый AppGraph (E1).
4. **«Нет данных» маскируется под «не опубликовано»** в 3 слоях: репозиторий (SCH-03 success(0)), воркер (WID-03 checkedKey), UI (SUI-02 hasSyncError не проброшен). Одна конвенция: различать «сайта нет» / «документ не найден» / «данных на дату нет» и честно показывать пользователю.
5. **Состояние не переживает навигацию** (when()-поддерево): костыли C3/returnTab/pending*/binding-петля карты — всё следствия ARC-01. Лечится Navigation-Compose одной волной (E4).

## Опровергнутые/снятые гипотезы (не тратить время)

- ❌ 404-страница WordPress попадает в парсер как «документ» — `downloadFileBytes` фильтрует по isSuccessful (проверено).
- ❌ Лексикографическое сравнение строк дат в UI расписания — агент 02 проверил всю цепочку: сравнения через ==/epoch/DAO-substr, формат согласован.
- ❌ Off-by-one колонок в парсере teachers.csv — индексы 3/4/5 корректны, прочерки реально в данных.
- ❌ TaskDao ORDER BY deadlineDate «нарушает конвенцию дат» — deadlineDate хранится в ISO (yyyy-MM-dd), лексикографика = хронология. Но смешение форматов задокументировать (DAT-04).
- ❌ Manifest-проблемы FGS — specialUse+property на месте, экспорт-компоненты закрыты.
