# Ревью: Карта колледжа

_Дата: 2026-10-01. Область: map. Ревьюер: босс (лично, после обрыва агента)._
_ВНИМАНИЕ: точный repro бага «третьего клика» требует запуска на устройстве/инструмент. Ниже — верифицированные по коду структурные баги + ранжированные гипотезы. Каждая гипотеза помечена confidence._

## Резюме и вердикт

Экран карты (1331 строка) — самый запутанный в проекте. Главная архитектурная проблема: **двусторонняя привязка `target`(ребёнок) ↔ `mapRoom`(родитель)** через `onRoomChanged`/`initialRoom`, которая в паре с `remember(initialTarget)`-сбросом и пересозданием поддерева при `when()`-навигации (ARC-01) делает состояние выбора кабинета хрупким. Баг «третий клик» — почти наверняка проявление этой хрупкости. Плюс hit-test тапа читает `scale/offset` во время зум-анимации → клики мимо при анимации.

## БАГ «ТРЕТЬЕГО КЛИКА» — анализ (ранжированные гипотезы)

### MAP-01 [high/bug] Двусторонняя binding-петля target↔mapRoom + сброс remember — confidence: СРЕДНЯЯ
- **Файлы**: `CollegeMapScreen.kt:193-197`, `CollegeScreen.kt:137,227,231`.
- **Механика**:
  ```
  var target by remember(initialTarget) { mutableStateOf(initialTarget) }  // :196
  LaunchedEffect(target) { onRoomChanged(target) }                          // :197
  ```
  Родитель: `mapRoom`(CollegeScreen:137) → `initialRoom = mapRoom`(:227) → `onRoomChanged = { mapRoom = it }`(:231).
  Цикл: тап → `target = room.number`(:398) → LaunchedEffect → `onRoomChanged` → `mapRoom` → `initialRoom` → `initialTarget = remember(initialRoom)`(:193) меняется → **`target` пересоздаётся** (`remember(initialTarget)` на :196).
- **Почему может ломаться на 3-м клике**: `remember(initialTarget){ mutableStateOf(...) }` УНИЧТОЖАЕТ и пересоздаёт state каждый раз когда initialTarget меняется. Если recomposition-порядок такой, что пересоздание `target` опережает/перехлёстывает следующий тап (особенно при быстром тапе, или когда `floorId` меняется и тянет рекомпозицию `MapCanvas`), значение `target` сбрасывается на echo-значение родителя, а не на новый тап. На 1-2 клике петля успевает stabilizироваться (RoomPanel ещё не появился/появился), на 3-м — рассинхрон. Точный порядок recomposition без запуска не гарантирован.
- **Связь с ARC-01**: переход в карточку преподавателя (`onOpenTeacher`) уничтожает экран (`when()`), возврат пересоздаёт с `initialRoom = mapRoom`. Комментарий на :128-130 ПРЯМО признаёт: «переход в карточку преподавателя уничтожает этот экран вместе с его remember-состоянием». binding-петля — костыль поверх этой дыры.
- **Фикс (тактический)**: разорвать петлю. `target` — ЕДИНСТВЕННЫЙ источник истины на экране; `onRoomChanged` вызывать только для информирования родителя, НО `initialRoom` НЕ должен обратно перезаписывать `target` при каждом эхе. Конкретно: `target = remember { mutableStateOf(initialRoom?.trim().orEmpty()) }` (без ключа initialTarget) + `initialRoom` читать только при ПЕРВОМ входе/явной смене извне (через отдельный `key`/`SavedStateHandle`). Тогда локальные тапы не сбрасываются эхом.
- **Фикс (системный)**: ARC-01 Navigation-Compose — состояние карты живёт в nav-backstack/SavedStateHandle, не в remember, пересоздание поддерева не теряет его.

### MAP-02 [high/bug] hit-test тапа читает scale/offset во время зум-анимации — confidence: ВЫСОКАЯ
- **Файл**: `CollegeMapScreen.kt:1074-1081` (`detectTapGestures`), `:1047-1067` (zoom-анимация).
- **Механика**: на каждый тап `LaunchedEffect(floorId, targetRoom?.id, viewW, viewH)`(:1047) запускает анимацию: zoom IN на кабинет (420мс) → `delay(600)` → zoom OUT (540мс) = **~1.5 секунды** scale/offsetX/offsetY в полёте. Тап-детектор(:1076-1078) считает `xNorm = ((pos.x - offsetX.value)/s)/imgW` используя ТЕКУЩИЕ (анимируемые) `scale.value`/`offsetX.value`. Тап во время анимации → координаты мапятся неверно → `hitTestRoom` промахивается → «не нажимается».
- **Почему «третий»**: 1-й тап — анимация ещё не шла (scale=1, статично), попадает. 2-й тап — часто в спокойном состоянии. Но если пользователь тапает в ритме ~раз в секунду, 3-й тап lands ровно в середину 1.5-секундной анимации от 2-го → промах. Это ДЕТЕРМИНИРОВАННО воспроизводится при определённом темпе тапов — сильная гипотеза.
- **Доказательство**: `s = scale.value`(:1076) читается в момент тапа, не snapshot-нуется к «rest» состоянию.
- **Фикс**: hit-test считать по «покойным» координатам, а не анимируемым: хранить отдельный `restScale`/`restOffset` (или `Animatable` target-значения) и использовать ИХ в hit-test; либо игнорировать тапы во время анимации (`if (isAnimating) return@detectTapGestures`), либо сократить/убрать zoom-анимацию (она косметическая). **Lazy-вариант: hit-test по target-значениям анимации** (`scale.targetValue`), а не `.value`.

### MAP-03 [medium/bug] pointerInput рестартует при смене viewH (RoomPanel меняет высоту) — confidence: СРЕДНЯЯ
- **Файл**: `CollegeMapScreen.kt:1074` (`pointerInput(floorId, viewW, viewH)`), `:405-410` (RoomPanel показывается при targetRoom!=null), `:390-403` (MapCanvas weight(1f)).
- **Механика**: MapCanvas в `Column` с `weight(1f)`. До первого тапа RoomPanel скрыт (targetRoom=null), после — появляется(:405), меняя высоту Column → `weight(1f)` перераспределяет → **viewH у MapCanvas меняется**. `viewH` — ключ `pointerInput(floorId, viewW, viewH)`(:1074) → тап-детектор ПЕРЕЗАПУСКАЕТСЯ (корутинa отменяется, новая стартует). Разные кабинеты → разная высота RoomPanel (title maxLines=2, note опционально :532) → viewH меняется на КАЖДОМ тапе → детектор постоянно рестартует. Тап в момент рестарта теряется.
- **Фикс**: (а) зафиксировать высоту RoomPanel (постоянная, не зависит от title/note длины) → viewH стабилен; либо (б) убрать viewW/viewH из ключей pointerInput (читать их через `BoxWithConstraints`-snapshot внутри, не как ключ); либо (в) `onSizeChanged` обновлять отдельный state, не рестартуя детектор.

### Итог по «третьему клику»
Наиболее вероятна **комбинация MAP-02 (анимация) + MAP-03 (рестарт pointerInput)**, обе дают «тап теряется» и обе детерминированы при реальном использовании. MAP-01 (binding-петля) — усугубляющий фон и корень при навигации туда-обратно. **Рекомендую: сначала MAP-02 (hit-test по targetValue, 3 строки) + MAP-03 (фикс высоты RoomPanel) — это с вероятностью ~80% чинит «третий клик» без большой Navigation-миграции.** Затем подтвердить на устройстве (или расширить `MapScreenShotTest` до инструментального repro с 3 тапами).
