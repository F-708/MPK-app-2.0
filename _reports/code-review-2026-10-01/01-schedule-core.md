# Ревью: Расписание — ядро (парсинг, сеть, репозиторий, кэш, воркер)

_Дата: 2026-10-01. Область: schedule-core. Ревьюер: босс (лично), с ЖИВОЙ проверкой сайта curl'ом._
_Статус находок: SCH-01 — ДОКАЗАНА живыми данными; остальные — по чтению кода._

## Резюме и вердикт

Система синхронизации спроектирована разумно (гейты кэша, транзакционная запись, фолбэки), но **не попадает в реальные URL сайта**, когда документ залит не по шаблону. Главный баг заказчика «1 октября расписание не синхронизируется» имеет доказанный root cause (SCH-01). Также есть структурная проблема: «документ не найден» маскируется под успех (SCH-03), а половинчатый гейт `shouldFetchDay` может оставлять день недокешированным (SCH-05).

## Критичные баги

### SCH-01 [critical/bug] Прямые URL не учитывают реальную схему публикации сайта — ДОКАЗАНО
- **Файлы**: `data/network/MpkNetworkClient.kt:39-61` (`buildDirectScheduleUrl`, `generateCandidateDirectUrls`), `data/repository/ScheduleRepository.kt:286-313` (`fetchAllGroupsForDate`), `MpkNetworkClient.kt:142-167` (портал-фолбэк в `fetchScheduleForGroup`).
- **Root cause** (3 слоя, все проваливаются одновременно):
  1. **Папка = месяц ЗАГРУЗКИ, не месяц ДАТЫ.** Реальный документ на 01.10.2026 лежит в `/wp-content/uploads/2026/09/` (залит в сентябре). Код всегда подставляет месяц целевой даты (`$yyyy/$mm` из calendar) → 404 на всех трёх прямых кандидатах.
  2. **Суффикс коллизии `-1`.** Реальное имя: `01.10.2026-raspisanie-uchashhihsya-1.doc`. Код пробует только без суффикса.
  3. **Портал-фолбэк слеп.** На `https://guo-mpk.by/raspisanie/` сегодня НЕТ ни одной прямой `.doc/.docx`-ссылки — только ссылки на event-страницы вида `/raspisanie/01-10-2026-raspisanie-uchashhihsya/?occurrence=2026-10-01`. `extractDocumentUrls` ищет `.doc` в HTML портала и не находит ничего. Реальный `.doc` лежит ВНУТРИ event-страницы, в iframe `view.officeapps.live.com/op/embed.aspx?src=<urlencoded .doc>`.
- **Доказательство (curl, 2026-10-01 ~19:50 MSK)**:
  ```
  404  /wp-content/uploads/2026/10/01.10.2026-raspisanie-uchashhihsya.doc
  404  /wp-content/uploads/2026/10/01.10.2026-raspisanie-uchashhihsya.docx
  404  /wp-content/uploads/2026/10/01_10_2026-raspisanie-uchashhihsya.doc
  200  /wp-content/uploads/2026/10/02.10.2026-raspisanie-uchashhihsya.doc   (завтра — случайно совпал шаблон)
  200 application/msword 107520  /wp-content/uploads/2026/09/01.10.2026-raspisanie-uchashhihsya-1.doc  ← РЕАЛЬНЫЙ
  портал 200: единственная ссылка на сегодня — event-страница; iframe внутри неё декодируется в РЕАЛЬНЫЙ URL
  ```
- **Почему «через раз»**: работает только когда файл залит в «правильную» папку и без суффикса (02.10 — да, 01.10 — нет).
- **Инфраструктура для фикса УЖЕ есть и не подключена**:
  - `MpkScheduleParser.extractDocumentUrls` (строки 182-192) умеет доставать `.doc` из officeapps-iframe c URL-decode — проверено вручную, декодирует корректно.
  - `MpkNetworkClient.generateCandidateEventUrls` (строки 63-73) строит ровно нужный event-URL — **МЁРТВЫЙ КОД**: в `app/src/main` ноль вызовов (grep), только два теста.
- **Фикс** (один путь для обоих фолбэков — `fetchAllGroupsForDate` и `fetchScheduleForGroup`):
  1. Прямые кандидаты: добавить месяц загрузки = месяц даты И предыдущий месяц (перехлёст публикаций), суффиксы `""`, `-1`, `-2`. Итого ≤ 3 имени × 2 месяца × 2 расширения — перебор дешёвый, 404 быстрые.
  2. Если прямые не дали: скачать event-страницы из `generateCandidateEventUrls(calendar)` → `extractDocumentUrls(eventHtml)` → скачать найденный `.doc`.
  3. Портал-фолбэк: из HTML портала брать и event-ссылки (`/raspisanie/<dd-mm-yyyy>-raspisanie-uchashhihsya/?occurrence=`), для каждой — шаг 2.
  4. Test: `ScheduleEventUrlTest` — фикстура event-HTML с iframe → `extractDocumentUrls` возвращает ожидаемый `.doc` (парсер уже умеет; тест фиксирует контракт). Живой смоук — `LiveNetworkSmokeTest` уже существует, дополнить.

### SCH-02 [high/bug] `fetchTeacherSchedule` — только один URL, те же слепые зоны
- **Файл**: `data/network/MpkNetworkClient.kt:250-289`.
- Прямой URL `/wp-content/uploads/$yyyy/$mm/$ddMmYyyy-raspisanie-prepodavatelej.doc` — без вариантов месяца загрузки/суффиксов/event-страниц. На портале сегодня есть event-страница `01-10-2026-raspisanie-prepodavatelej-2` (обрати внимание: `-2` и без `?occurrence` у преподавательской 01.10 — шаблон имени ещё и плавает). Расписание преподавателей будет отваливаться тем же образом, что и студенческое.
- **Фикс**: тот же механизм кандидатов + event-страницы, вынести в общую функцию (см. кросс-доменный паттерн в сводке).

## Баги «через раз» / плавающие

### SCH-03 [high/bug] «Документ не найден» маскируется под успех
- **Файл**: `data/repository/ScheduleRepository.kt:232-237`.
- `fetchFailed` ставится только когда `downloadFileBytes` бросил исключение; 404 → `null` → `continue` → `documentFound=false`, `fetched` пуст → ветка `else -> Result.success(0)` → тост «новых данных пока нет». Пользователь и поддержка видят «всё ок, просто нет данных», хотя на самом деле сайт ДОСТУПЕН и документ СУЩЕСТВУЕТ, просто мы не угадали URL. Диагностика (`SyncDiagnosticInfo`) заполняется только в одиночном пути `fetchScheduleForGroup`, в каталожном пути `fetchAllGroupsForDate` — нет вообще.
- **Фикс**: в каталожном пути тоже писать `_diagnosticInfo` (проверенные URL, коды); при `documentFound=false` И хотя бы одном 404 — возвращать отдельный статус «документ не найден ни по одному кандидату» (не failure, но и не тихий success(0)), выводить его в UI диагностики.

### SCH-04 [medium/bug] `nextSchoolDay` пропускает только воскресенье
- **Файл**: `data/repository/ScheduleRepository.kt:487-493`.
- `while (cal.get(DAY_OF_WEEK) == SUNDAY)` — суббота считается учебным днём. Если колледж работает по шестидневке — верно; если по пятидневке — «завтра» в субботу/понедельник будет тратить запрос на несуществующий документ и показывать пустое «завтра». Требует подтверждения у заказчика (какая неделя в МГПК). Каникулы не учитываются вообще — в каникулы каждый синк = бесполезный поход на сайт (терпимо, но стоит знать).

### SCH-05 [medium/bug] `shouldFetchDay`: ровно половина каталога = «день уже распарсен»
- **Файл**: `data/repository/ScheduleRepository.kt:25-26`.
- `alreadyParsedGroups < (catalogSize + 1) / 2` — если в кэше ровно половина групп (например, документ был неполным/старым), гейт говорит «не качать», и день навсегда остаётся наполовину пустым без `force`. Порог «половина» сам по себе эвристика: полный документ даёт ~100% групп.
- **Фикс**: хранить в БД метку «дата X распарсена полным документом N групп» (одна строка в отдельной таблице или колонка-флаг), гейт сверять с ней, а не считать группы эвристически.

### SCH-06 [medium/bug] Дата из заголовка документа может переклеить день (applyHeaderDate)
- **Файл**: `data/network/MpkScheduleParser.kt:120, 707-749`.
- `parseFile` → `applyHeaderDate` перезаписывает `dateString` уроков датой, распознанной из текста документа (включая текстовый формат «1 октября» с подстановкой текущего года на строке 745-747). Если сайт отдаёт под именем «01.10» документ-изменение, озаглавленный другой датой, или недельный шаблон без даты — уроки могут лечь не под ту дату, а кэш-гейт по `todayStr` их потом не найдёт. Год из `Calendar.getInstance()` на стыке года (31.12 → публикация на 01.01 следующего года, текст «января» без года) даст НЕВЕРНЫЙ год.
- **Фикс**: в `applyHeaderDate` сверять распознанную дату с `targetDate`; при расхождении — приоритет targetDate + лог в диагностику. Для текстовых месяцев без года: если полученная дата в будущем дальше 6 мес от сегодня — взять предыдущий год (и наоборот).

## Архитектура и ООП

- **ARC-замечание (medium)**: `ScheduleRepository` — god-объект на 530 строк: студенческое расписание + преподавательское + кэш-гейты + URL-фолбэки + prune. Выделить `ScheduleUrlResolver` (все кандидаты URL + event-страницы + портал) — он нужен трём вызывающим (см. SCH-01/02) и легко тестируется в отрыве от сети.
- `teacherLessonDao = null` захардкожен в конструкторе (строка 71) — офлайн-кэш преподавателей фактически МЁРТВ в бою, если никто не передаёт DAO. Проверить создание репозитория в `AppViewModel`/`MainActivity` (см. отчёт 08-architecture).
- `MpkScheduleParser` — object на 1423 строки с `lastParseStats` как глобальным mutable-состоянием: параллельные вызовы (воркер + UI) гонят друг друга по статистике. Не критично (статистика диагностическая), но `@Volatile`/flow-локальная передача чище.
- Три стратегии парсинга (grid/cells/line) с `runCatching` и склейкой ошибок — хорошо, не ломать.

## Производительность

- `fetchAllGroupsForDate` на каждый день гоняет `parseFileAllGroups` = `parseFileRaw` для КАЖДОЙ группы каталога (см. комментарий на 227-232). Каталог ~N групп → N полных проходов по документу. При 100+ групп это тяжело на мобильном. Помечено как «намеренно», но кандидат на оптимизацию: один проход с матчингом всех групп (SCH-perf, low — работает, но медленно).
- `portalHtml()` качается заново в каждом вызове без кэша — при синке двух дней (сегодня+завтра) портал качается дважды (`fetchAllGroupsForDate` вызывается в цикле дней). Мелочь: кэш на 5 минут.
