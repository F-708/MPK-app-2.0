# «Мой Политех — Преподавателю»: UX-дизайн

Фаза 1 (изоляция). Автор: UX/Android-дизайнер консилиума.
База: стиль v2.5 («бумажный», ColorTopBar, рамки 1–2dp, скругления 2–3dp, `ui/theme/Tokens.kt`), принципы android-ux (M3-аудит, hit-зоны, контраст, семантика).
Условие: без обязательной регистрации, офлайн-first (`teacher_lessons` уже работает).

## 1. Information architecture

**3 вкладки** (не 4):

| Вкладка | Содержимое |
|---|---|
| **Сегодня** | «Моё сегодня» + сегмент Сегодня/Завтра; карточки пар со статусами и действиями |
| **Неделя** | Полоса дат Пн–Сб + список пар выбранного дня; компактный режим «нагрузка» (сетка) |
| **Ещё** | Группы (поиск + расписание группы), карта колледжа, звонки, сменить преподавателя, настройки уведомлений/виджетов |

**Обоснование.** У преподавателя одна доминирующая задача: «что у меня дальше и где». Всё остальное — справочное, низкочастотное. Три вкладки = меньше мишеней в нижней панели, крупнее hit-зоны (важно для 50+, §9), «Сегодня» всегда первый тап.

**Отклонённая альтернатива:** зеркалить ученические 4 вкладки (Расписание/Уроки/Звонки/Другое). «Уроки» (материалы/оценки/ДЗ) — ученическая сущность; звонки — справочник на раз в месяц, не заслуживают вкладки. Четвёртая вкладка размазала бы внимание.

**Отклонённая альтернатива 2:** одна вкладка «Расписание» с табами внутри (сегодня/завтра/неделя). Лишний уровень навигации; сегмент Сегодня/Завтра живёт на первой вкладке, Неделя — отдельная, т.к. это другой ментальный режим («планирую», а не «смотрю сейчас»).

Свайп между вкладками сохраняем (уже есть в v2.5, мышечная память).

🔴 **Спорно:** нужна ли сетка вообще в v1. Список «полоса дат + карточки дня» закрывает 90% задач; сетка — второй приоритет, можно отложить.

## 3. Главный экран «Моё сегодня»

Структура сверху вниз:
1. **Дата** («вт, 7 октября») — крупно, это первый вопрос пользователя.
2. **Карточки пар в хронологическом порядке**, каждая в `AppCard`:
   - **Статус-чип**: `● ИДЁТ` (акцентный синий + точка), `СЛЕДУЮЩАЯ` (нейтральный), `ПРОШЛА` (приглушённый текст 60%). Статус всегда **текстом + цветом**, не только цветом (§9).
   - **Время** 09:50–11:20 — крупнее всего в карточке (глазный якорь).
   - **Предмет** — строка bodyLarge.
   - **Чипы групп** — кликабельны → экран группы (§5). Несколько групп на паре = несколько чипов.
   - **Чип кабинета** — кликабельный → карта с маршрутом (механика v2.5, 1-в-1).
   - Кнопка **⚑ маршрут** — дубль чипа кабинета для крупных пальцев, hit ≥48dp.
3. Автопрокрутка к «идёт/следующая» при открытии — пользователь не листает к текущей паре вручную.

**«ИДЁТ» вычисляется локально** по времени пары (уже есть логика now/next в `NowNextWidgetProvider` — переиспользовать, не писать заново).

**Пустой день / выходные:**
- Нет пар: плейсхолдер-карточка «Пар нет 🎉» + «Следующая пара: ср, 8 октября, 09:50 — Математика, 241» + кнопка «Открыть неделю». Никакой пустоты экрана — всегда есть следующий шаг.
- Выходной: тот же плейсхолдер + дата ближайшего учебного дня (берём из `ScheduleRepository.nextSchoolDay` — уже существует).
- Вечером все пары «ПРОШЛИ»: показываем их приглушёнными (история дня) + блок «Завтра: …» сверху — мост к сегменту «Завтра».

**Отклонённая альтернатива:** скрывать прошедшие пары. Преподавателю полезно видеть день целиком (отчитаться, вспомнить); приглушение решает проблему визуального шума.

## 4. «Моё завтра» и недельный вид

**Завтра** — сегмент-переключатель `[Сегодня|Завтра]` на первой вкладке, а не отдельный экран: контент идентичен «Сегодня» (те же карточки, без статусов «идёт/прошла» — только список). После 20:00 [ASSUMPTION] сегмент «Завтра» подсвечен бейджем — вечерний сценарий «что завтра» не менее частый, чем утренний.

**Неделя** — формат **«полоса дат + список дня»** (см. ASCII §1):
- Горизонтальная полоса Пн–Сб, текущий день выделен рамкой, под каждой датой бейдж числа пар (0 = прочерк) — нагрузка видна одним взглядом.
- Ниже — карточки пар выбранного дня, те же компоненты.
- Свайп влево/вправо по области списка = предыдущая/следующая неделя (единственный дополнительный жест, опционален — всё достижимо тапом по дате).

**Обоснование формата.** На телефоне 360dp вертикальный список дня читается без увеличения; карточки уже спроектированы и переиспользуются. Неделя = «выбрал день → читаю список», один паттерн на весь экран.

**Сетка день×пара** — компактный режим-переключатель, не основной вид: 6 колонок × до 8 пар на 360dp даёт ячейки ~52×56dp, куда влезает только №кабинета + цвет предмета. Как полноценный вид на телефоне нечитаема (для 50+ особенно), но как **обзор нагрузки** («окна», плотность недели) ценна. Тап по ячейке → карточка пары в bottom sheet.
🔴 Спорно: делать ли сетку в v1 или отложить (см. §1).

**Отклонённая альтернатива:** календарь-месяц как основной вид недели. Месячная сетка на телефоне = ячейки 48×48dp максимум, расписание в них не поместится; месяц нужен редко (архив) — остаётся в `CalendarArchiveDialog` (уже есть).

## 5. Экран группы

**Нужен, да.** Сценарии преподавателя: «чем занята группа в моё окно», «когда у ИС-21 практика — перенести консультацию», «кто ещё ведёт у группы». Отклонять нельзя: это единственная связь учителя с общим расписанием колледжа.

**Доступ за ≤2 тапа:**
1. **1 тап:** чип группы в любой карточке пары (Сегодня/Завтра/Неделя/виджет) → `GroupScheduleScreen` (уже существует, 1-в-1).
2. **2 тапа:** вкладка «Ещё» → «Группы» → поиск/список → расписание группы. Список сортирован: **сначала группы текущего преподавателя** (вычисляются из `teacher_lessons`), потом все — в 90% случаев нужен тап по первой секции.

Отдельная вкладка «Группы» не нужна: частота использования низкая, а путь через чип пары — естественный (преподаватель смотрит группу в контексте своей пары).

## 6. Виджеты

Переиспользуем три провайдера v2.5, меняя источник данных группа → `teacher_lessons`:

| Виджет | Размер | Содержимое | Кликабельно |
|---|---|---|---|
| **Следующая пара** | 4×1 (осн.) и 2×2 | Время, предмет, группа(ы), кабинет, крупно «через 25 мин» | Кабинет → карта с маршрутом (action-кнопка ⚑); остальная площадь → «Сегодня» |
| **Моё сегодня** | 4×2 | До 4 пар дня со статусами + «ещё N» | Каждая строка → экран «Сегодня» (скролл к паре); кабинет в строке → карта |
| **Отсчёт до пары** | 2×2 | «До пары 25:00» + предмет следующей | Целиком → «Сегодня» |

**Обоснование набора.** Виджет «следующая пара» — главный для преподавателя: телефон на столе, один взгляд = когда/что/где. Отсчёт закрывает тревогу «не опоздаю». «День целиком» — для утра.

**Отклонено:** виджет звонков (есть у студентов, преподавателю общий звонок почти не нужен — пары идут по звонкам и так); виджет недели (информационная плотность выше порога читаемости home screen).

Кнопка маршрута в виджете 4×1 обязательна: путь «взглянул → пошёл» без разблокировки в полный экран — главный сценарий между парами.

[ASSUMPTION] Glance vs RemoteViews: текущие провайдеры v2.5 на RemoteViews — оставляем технологию как есть, меняем только данные и layout-файлы.

## 7. Уведомления

Принцип: **максимум 2–3 уведомления в день, каждое должно окупать своё существование.**

| Что | Когда | Канал | Default |
|---|---|---|---|
| **Утренняя сводка дня** | 07:30 (настраиваемо): «Сегодня 5 пар, первая 09:50 — Математика, 241» | `day_summary` (low) | вкл |
| **Напоминание о паре** | за 10 мин (настраиваемо), **только если**: кабинет отличается от кабинета предыдущей пары ИЛИ это первая пара дня | `lesson_reminder` (default), action «Маршрут» | вкл |
| **Изменения/замены** | когда фоновый синк (`ScheduleCheckWorker`) обнаружил diff в расписании преподавателя: «Завтра 3-я пара отменена» / «Кабинет 241→305» | `schedule_changes` (high) | вкл |

**Quiet hours: 21:00–07:00** для всех каналов; сводка, попавшая в quiet hours, откладывается до 07:00. Изменения ночью тоже молчат до утра — срочность замены с вечера покрывает утренняя сводка («⚠ 3-я пара отменена»).

**Отклонено:** напоминание о каждой паре — спам (у преподавателя 4–6 пар в день = 6 уведомлений, канал отключат вместе с полезными). Отклонено: push о заменах в реальном времени — нет бэкенда; diff после периодического синка достаточно.

Изменения считаются по diff «было в кэше vs пришло из сети» по ключу (дата, номер пары) — технически дёшево, т.к. кэш Room уже хранит старую версию. [ASSUMPTION]

Лимит: не более 1 сводки об изменениях на один синк (объединяем все diff одного дня в одно уведомление).

## 8. Замены и ручные правки

**Рекомендация: локальные override-записи поверх синка. Честная сложность: низкая-средняя, бэкенд не нужен.**

UX-паттерн:
1. На карточке пары (только сегодня/завтра) кнопка **«Править»** (⋮ или иконка-карандаш, hit 48dp).
2. Bottom sheet, три варианта одним списком:
   - «Другой кабинет» → выбор из комнат карты (переиспользуем `college_map.json`) или свободный ввод;
   - «Пары нет» (отмена);
   - «Замена — веду не я» (пара остаётся в списке, помечается «ЗАМЕНА», преподавателю не напоминает).
3. Правленая карточка: маркер **✎ «ваша правка»** + кнопка «Отменить правку». Правка визуальна отделена от официальных данных — пользователь всегда видит, где синк, где его запись.
4. После следующего синка: если официальный документ изменил эту пару — правка **автоматически сбрасывается** (официальные данные победили) с тихим уведомлением «Расписание обновлено, ваша правка на вт 3-я пара сброшена». Если синк пару не тронул — правка живёт до конца дня.

Хранение: таблица Room `teacher_overrides(date, lessonIndex, groupCode, newRoom?, status: CANCELLED/SUBSTITUTED/ROOM)`, версия БД +1 с явной миграцией (конвенция №2 SKILL.md — без `fallbackToDestructiveMigration`!). Слияние — на уровне репозитория: official + overrides → UI-модель.

**Флаг «меня нет / замена» с публикацией студентам — 🔴 ЗА рамками v1.** Студенческое приложение узнаёт о замене только из официального документа расписания; чтобы локальный флаг учителя увидели студенты, нужен сервер приёма изменений + модерация (завуч не пропустит самоуправство). Это продукт-решение уровня «система замен колледжа», не фича приложения. В v1 правка — **личная** (мой кабинет, мои напоминания).

**Отклонено:** редактирование полного расписания (перенос пары на другой день, изменение времени) — резко усложняет модель слияния с синком ради редкого сценария. Отклонено: «режим правок с историей и экспортом» — over-engineering.

## 9. Доступность для 50+

Целевая аудитория шире студенческой по возрасту — закладываем с первого экрана:

1. **Размеры шрифтов:** body ≥16sp (у студентов местами 12–14sp — для учителя поднять), время пары 20–24sp, статус 13sp caps. Полное уважение системного font scale (до 2.0x) — верстка не должна ломаться: карточки растут по высоте, ничего не обрезается. `Tokens.kt` сейчас: ButtonText 12sp, ChipText 11sp — 🔴 **для преподавательского приложения поднять ChipText ≥13sp, ButtonText ≥14sp**, иначе чипы групп/кабинетов нечитаемы.
2. **Hit-зоны ≥48dp.** `Tokens.HitTarget = 44dp` — по M3/WCAG минимум 48. 🔴 Поднять токен до 48dp (или завести `HitTargetTeacher = 48dp`). Все чипы, кнопки маршрута, сегменты — ≥48dp; между кликабельными чипами зазор ≥8dp (промах по «кабинету» не должен вести на «группу»).
3. **Контраст:** WCAG AA 4.5:1 для текста, 3:1 для границ/иконок. Приглушение «прошедших» пар — не ниже 60% opacity эквивалента (проверить контраст, а не «красиво»).
4. **Минимум жестов:** всё достижимо тапом. Свайп вкладок保留 (есть в v2.5, не мешает тап-навигации). Никаких long-press как единственного способа действия, никаких drag.
5. **Статусы не только цветом:** «ИДЁТ/СЛЕДУЮЩАЯ/ПРОШЛА» — текст + точка-маркер (дальтоники, солнце на экране).
6. **TalkBack:** карточка пары — `semantics(mergeDescendants = true)` одним блоком («Идёт, Математика, 09:50–11:20, группа ИС-21, кабинет 241»); заголовки дат — `heading()`; у чипов отдельные contentDescription («Кабинет 241, открыть маршрут»).
7. **Без тёмной темы как обязательной** [ASSUMPTION]: «бумажный» светлый стиль — дефолт; тёмная — если уже есть в v2.5, наследуем без новых затрат.

## 10. Переход из ученического приложения: что переиспользовать 1-в-1

Единый визуальный язык — обязательное условие: преподаватель и студент могут показывать экраны друг другу («вот ваше расписание» / «вот моё»).

| Компонент v2.5 | В преподавательском | Как |
|---|---|---|
| `AppCard` (2dp скругление, 1dp рамка ColorBorderLight) | Карточка пары, карточка дня | **1-в-1** |
| `Tokens.kt` | Все размеры | 1-в-1 + правки §9 (hit 48, шрифты) 🔴 |
| Чип кабинета → карта с маршрутом | Действие «маршрут до кабинета» | **1-в-1** (уже кликабельный) |
| `GroupScheduleScreen` | Экран группы из чипа | **1-в-1** |
| `TeacherCardPageWrapper` (сегодня/завтра/календарь преподавателя — работает) | Основа «Моё сегодня» | 1-в-1, статусы/действия добавляются |
| `SearchBar`, `TeachersPage` (поиск по ФИО) | Онбординг «Кто вы?» | 1-в-1 |
| `ScheduleRepository`, `teacher_lessons`, `ScheduleCheckWorker` | Данные и фон-синк | 1-в-1, источник = выбранный teacher |
| `NowNextWidgetProvider`, `TodayScheduleWidgetProvider`, `BellCountdownWidgetProvider` | Виджеты §6 | Layout+данные меняются, механика та же |
| `CalendarArchiveDialog`, `nextSchoolDay` | Календарь, «следующий учебный день» | 1-в-1 |
| `CollegeMapScreen` + маршруты | Карта из «Ещё» и чипов | 1-в-1 |
| Цвета: ColorTopBar, ColorBgMain, ColorBorderLight | Вся тема | 1-в-1 |

**Нового кода минимум**: экран «Неделя» (полоса дат), bottom sheet правок (§8), таблица overrides + миграция, diff-логика уведомлений об изменениях, 3 layout-файла виджетов. Всё остальное — перестановка существующего вокруг новой оси «преподаватель вместо группы».

**Архитектурный вопрос 🔴 (не UX, но помечаю для консилиума):** отдельный APK/build variant vs режим внутри одного приложения (переключатель «Я: студент/преподаватель» в «Другое»). UX-дизайнер за **один APK с режимом**: одна установка на кафедре, общие компоненты живут в одном модуле, расхождение токенов (§9) решается темой режима. Но это решение за архитектором.
