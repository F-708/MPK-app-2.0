# Teacher App — позиция ПРОДУКТОВОГО СТРАТЕГА
Фаза 1 консилиума, 2026-10-07. Автор: product-strategist agent.

## 0. Главный стратегический тезис (до разделов)

**«Отдельное приложение» ≠ отдельная кодовая база.** Единственно оправданная форма поставки — **build flavor `teacher` того же проекта** `com.politex` (отдельный APK, отдельное имя/иконка, общий код). Прецедент уже работает в проекте: flavor `admin` изолирует students.csv [VERIFIED: SKILL.md конвенция №3, app/src/admin/assets/]. Новый форк кодовой базы при аудитории ~100 человек — гарантированная смерть обоих приложений на поддержке. Всё ниже исходит из этого.

## 1. Позиционирование и ЦА

**Позиционирование:** «Преподаватель МГПК» — личный рабочий день преподавателя: МОИ пары, МОИ кабинеты, МОИ группы. Не «ещё одно расписание», а смена оси: преподаватель — первоклассная сущность, открывающая приложение, а не строка в каталоге из ученического app.

**ЦА:**
- Ядро: ~100 преподавателей МГПК [VERIFIED: teachers.csv ~100 строк, ФИО;должность;предметы;...].
- Расширение: администрация (зам. директора по УР — потребитель сводок нагрузки/замен).
- Android-only. [ASSUMPTION: среди преподавателей 50+ доля Android высока; iOS-сборка нерентабельна при 100 пользователях — принимаем потерю iOS-меньшинства.]
- Ключевое отличие от студентов: преподаватель пользуется приложением **между парами, на ходу, 5-10 раз в день короткими сессиями** → продукт = виджет + уведомление + один экран «мой день», а не «приложение с навигацией».

**Расширение на другие колледжи:** НЕТ до v3. Парсер завязан на конкретный .doc-формат guo-mpk.by [VERIFIED: TeacherScheduleParser.kt — regex под таблицу ║/│, GROUP_REGEX под код групп МГПК, MpkNetworkClient.fetchTeacherSchedule]. Мультиколледж = другой продукт с другим парсингом, другой дистрибуцией, другой поддержкой. Пометить как опцию, не как roadmap-обязательство.

## 3. Киллер-фичи — трезвая оценка

| Фича | Вердикт | Уверенность | Комментарий |
|---|---|---|---|
| Виджет «моя следующая пара: время/кабинет/группа/предмет» | **КИЛЛЕР №1** | 🟢 | Ежедневный, мгновенный, данные готовы. Теперь-виджеты уже существуют — замена источника |
| Уведомление «через N мин твоя пара в каб. X» | **КИЛЛЕР №2** | 🟢 | Переиспользует BellTimerService/BellCountdownNotifier [VERIFIED: util/BellTimerService.kt] |
| Нагрузка: пары по дням/неделям, итог часов по группам/предметам | **КИЛЛЕР №3** | 🟢 | Реальная боль: тарификация, отчёты завучу, «сколько у меня в четверг». Почти бесплатно поверх teacher_lessons |
| Список «мои группы + предметы + кабинеты» | Да, в нагрузку | 🟢 | TeacherInsights уже считает subjects/rooms по фамилии [VERIFIED: TeacherInsights.kt] |
| Замена «меня сегодня нет / заменяет X» | Да, но БЕЗ бэкенда | 🟡 | MVP-версия: сгенерировать готовое сообщение (дата, номера пар, группы, кабинеты) → share в Viber завучу/чату. Полный цикл (автоназначение, уведомление администрации) = v2.0 с сервером, при 100 юзерах не окупается. [ASSUMPTION: коммуникация по заменам в МГПК идёт через Viber/телефон, не через систему] |
| Маршрут «кабинет→кабинет между парами» | Нишевое | 🟡 | Ценно новичкам и при кросс-корпусных парах. Дёшево (RouteFinder есть) — делаем в v1.1, не в MVP |
| Планы занятий / материалы к своим урокам | Спорно | 🟡 | Просмотрщики PDF/DOCX с рисованием уже есть — стоимость низкая. Риск: у преподавателей бумажный план-конспект по требованиям, приложение его не заменит. Формат v1.1: «прикрепить файл к паре», без синка и шаринга студентам |
| Журнал посещаемости | **НЕТ** | 🔴 | Дублирует официальный журнал, вводит персональные данные студентов в неофициальное ученическое приложение, создаёт юридическую ответственность и поддержку. Классический overkill |
| Выставление оценок студентам | **НЕТ** | 🔴 | То же: официальный (электронный) журнал — единственный легитимный канал. [ASSUMPTION: МГПК ведёт официальный электронный журнал; если нет — вердикт не меняется, т.к. локальный журнал без синка никому не нужен] |

## 4. MVP и roadmap

### v1.0 «teacher» (обязательно на релиз)
1. Первый запуск: поиск себя в teachers.csv → фиксация (surnameKey) [VERIFIED: TeachersRepository, TeacherInsights.surnameOf].
2. Главный экран «Мой день»: сегодня/завтра/календарь, cache-first + фоновый синк [VERIFIED: TeacherScheduleTab/loadTeacherDay — фактически перенос готового экрана].
3. Нагрузка: неделя по дням + часы по группам/предметам (агрегат teacher_lessons).
4. Виджет «следующая пара» + виджет «мой день».
5. Уведомление до начала своей пары (настраиваемый интервал).
6. Звонки-таймлайн (как есть).
7. Карта колледжа (как есть, без спец-маршрутов).
8. CUT-гейт сборки: нет students.csv, нет ученических экранов.

Оценка объёма: ~70% кода существует; новая работа — flavor-конфигурация, home-перестановка, экран нагрузки, перенацеливание виджетов/уведомлений. [ASSUMPTION: 2-3 недели агентной разработки волнами по 2-3 агента с компиляцией после каждой — по конвенциям SKILL.md.]

### v1.1 (через 1-2 месяца по фидбеку)
- «Замена» share-сообщением (Viber).
- Маршрут между кабинетами пар с бюджетом перемены.
- Материалы/план к своей паре (локально).
- Экспорт недельной нагрузки (PDF/текст) для завуча. [ASSUMPTION: завуч принимает неформальную выгрузку — уточнить до разработки!]

### v2.0 (только если v1 доказал ценность)
- Backend-lite (Firebase/Forms) для цикла замен: статус «нет сегодня» виден администрации, автопредложение заменителя из TeacherInsights (кто ведёт тот же предмет, у кого окно).
- Режим администрации: сводка «кто ведёт / кого нет / свободные преподаватели».
- Решение о мультиколледжности — отдельный продуктовый анализ, не раньше.

### Критерии успеха (измеримые)
| Метрика | Цель | Как мерим без аналитики |
|---|---|---|
| Установки | ≥60 из ~100 за 3 мес 🟡 | Счётчик загрузок APK/QR + опрос на педсовете. [ASSUMPTION: базовая конверсия неизвестна — цель калибруется после месяца] |
| WAU/MAU | ≥0.5 (ежедневный инструмент) | Разовый анонимный опрос «открываете ли ежедневно» — телеметрию НЕ заводим (100 юзеров, приватность, стоимость) |
| Виджет поставлен | ≥40% установивших | Опрос |
| Ценность для администрации | ≥1 кейс/мес «спасли от накладки замены» | Интервью с зам. по УР |
| Стабильность | crash-free ≥99.5% | Локальные логи + жалобы; Play-консоль если дойдём до Play |

## 5. Риски продукта

1. **Аудитория 100 человек — стоит ли?** Да, ПРИ условии flavor-модели: предельная стоимость teacher-сборки мала, код уже написан студентами и живёт дальше. НЕТ при отдельной кодовой базе — удвоение поддержки убьёт оба приложения. 🟢
2. **Поддержка двух приложений.** Митигация: один репозиторий, один CI, общие Room-миграции (конвенция №2 SKILL.md: любая миграция обязательна и тестируется — teacher_lessons уже в той же MpkDatabase v2). Риск flavor-специфичных багов — средний. 🟡
3. **Зависимость от сайта колледжа.** Расписание преподавателей — .doc, публикуется нерегулярно; логика «ещё не опубликовано» уже есть [VERIFIED: CollegeScreen.kt:1429]. Качество продукта = дисциплина завуча, мы не управляем. Митигация: кэш + понятная плашка + уведомление «расписание на завтра появилось». 🟡
4. **Хрупкий парсер.** Формат документа может поменяться без предупреждения (regex-эвристики ║/│, GROUP_REGEX) [VERIFIED: TeacherScheduleParser.kt]. Митигация: юнит-тесты на реальных документах, fallback-сообщение. 🟡
5. **Приватность.** teachers.csv (телефоны/email) уже shipped в standard-сборке — teacher-сборка новых данных не добавляет. Жёстко: никаких студенческих данных (гейт сборки). Персональные данные студентов в журнале/оценках — причина №1 отказа от этих фич. 🟢
6. **Как мерить ценность без аналитики.** Сознательное решение: при N=100 телеметрия дороже инсайта. Метрики — через дистрибуционный счётчик и живые интервью (см. §4). Риск: решения вслепую после v1.1 — принять. 🟡
7. **Bus-factor.** Приложение школьника-разработчика для взрослой аудитории с иной планкой надёжности. Митигация: документирование (SKILL.md уже есть), консервативный MVP без серверов. 🟡
8. **iOS-преподаватели исключены.** Принять; при сильном запросе — PWA-минимум (только просмотр) в v2+. 🔴 по вероятности запроса — не планируем.

## 6. Дистрибуция (кратко)

- **Канал:** прямой APK (как ученическое приложение) [ASSUMPTION: «Мой Политех» уже распространяется вне Play — механику переиспользуем]. QR-код + ссылка на странице колледжа / в учительском Viber-чате.
- **Точка захвата:** педсовет — 10-минутная презентация «ваш виджет на домашний экран», помощь в установке на месте (аудитория 50+, это критично).
- **Апсейл администрации:** завуч получает сводки нагрузки → становится внутренним промоутером.
- **Обновления:** in-app проверка версии + тот же QR; Google Play (хотя бы internal/closed track) — в v1.1, если апдейты станут частыми, ради автообновления 60+ устройств без ручной рассылки.
- Онбординг: 3 экрана, поиск фамилии, разрешение на уведомления, установка виджета — всё в первых 60 секундах.

### Итоговое стратегическое резюме (3 строки)
1. Не новое приложение, а **новый flavor** — 70% кода уже есть и проверено в бою.
2. MVP = «мой день + нагрузка + виджет + уведомление о своей паре»; журналы/оценки/посещаемость — отклонены как overkill и юр-риск.
3. Замена — только share-сообщением до v2; никакой сервер не окупается при N=100.
