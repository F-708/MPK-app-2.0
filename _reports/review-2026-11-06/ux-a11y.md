# UX + Accessibility ревью «Мой Политех» (v2.5 / ветка v2.4-stable)

Дата: 2026-11-06 · Ревьюер: rev-ux-a11y (read-only) · Код не менялся, gradle/Roborazzi не запускались.

**Метод.** Эвристическая оценка Нильсена (10 эвристик) + аудит доступности по WCAG 2.1 AA и
Android accessibility (TalkBack, touch target 48×48dp, `contentDescription`/`semantics`, fontScale).
Источник — исходники `app/src/main/java/com/politex/**` (75 файлов UI), тема `ui/theme/*`,
раскадровки `promo/shots`, `app/src/test/screenshots`. Контраст считался по WCAG-формуле
(relative luminance) для всех 8 тем × светлая/тёмная, для бейджей — с учётом 12 %-подложки.

**Рамка.** Заказчик: «визуально устраивает, есть баги». Поэтому ниже — не вкусовщина, а барьеры
(что-то нельзя сделать) и раздражители (что-то бесит при каждом использовании). Аудитория 16–50 лет,
часть — со слабым зрением; крупный системный шрифт и TalkBack считаем нормой, а не краевым случаем.

**Статус правок (обновлено 2026-11-06, ~17:55).** Патч-готовый план — в `ux-fixes-backlog.md`.

## Находки

Формат: `Приоритет / Имя` → **Где** → **Что видит/чувствует** → **Нарушение** → **Фикс** → **Проверка**.

### [P0] Удаление задания только свайпом
**Где:** `app/src/main/java/com/politex/ui/screens/TasksScreen.kt:738-822` (`SwipeToDeleteBox`), подсказка `:167` («Свайпните влево, чтобы удалить»), красная иконка `:803-811`.
**Что видит/чувствует:** пользователь TalkBack обводит карточку задания и не находит ни одной кнопки удаления: жест `detectHorizontalDragGestures` (`:771`) не имеет `CustomAccessibilityAction`. Иконка корзины сидит в подложке (`:795-812`), не кликабельна, но объявляется как «Удалить» — TalkBack фокусируется на надписи без действия. Человек с тремором/крупными пальцами либо не удалит задание, либо удалит случайно.
**Нарушение:** Nielsen #7 (гибкость и эффективность) + #3 (контроль); WCAG 2.5.1 Pointer Gestures (жест траектории без альтернативы), 2.1.1 Keyboard (нет доступного действия).
**Фикс:** добавить второй путь: долгое нажатие на карточку → контекстное меню «Удалить», либо `Modifier.semantics { customActions = listOf(CustomAccessibilityAction("Удалить задание") { onDelete(); true }) }` в `SwipeToDeleteBox`; иконку-подложку пометить `contentDescription = null` (декоративная), т.к. подсказка уже озвучивается текстом.
**Проверка:** TalkBack → фокус на карточке → «Действия» содержит «Удалить задание»; Compose-тест `onNodeWithText(task.title).performSemanticsAction(SemanticsActions.CustomActions)`.

### [P0] Вес предмета нельзя задать через TalkBack
**Где:** `app/src/main/java/com/politex/ui/screens/GradesScreen.kt:762-802` (`WeightSlider`), вызов — экран «Настройки предмета».
**Что видит/чувствует:** слайдер нарисован `Canvas`, значение меняется через `pointerInput { detectTapGestures / detectHorizontalDragGestures }` (`:776-789`). Семантики нет: TalkBack объявляет пустую область, `adjust`/`setProgress` недоступны. Слепой пользователь физически не может настроить вес контрольной/лабораторной — а от весов зависит средний балл, т.е. **оценка в зачётке**.
**Нарушение:** WCAG 4.1.2 Name, Role, Value; 2.1.1 Keyboard; Android: кастомный контрол обязан публиковать `progressBarRangeInfo`.
**Фикс:** `Modifier.semantics { progressBarRangeInfo = ProgressBarRangeInfo(value/100f, 0f..1f); setProgress { onValueChange((it*100).roundToInt()); true }; contentDescription = "Вес: $value%" }` + `role = Role.Adjustable`; либо заменить на `Slider` из M3 с кастомным треком.
**Проверка:** TalkBack: свайп вверх/вниз меняет вес и озвучивает «Вес 40 процентов»; Compose-тест на `SemanticsActions.SetProgress`.

### [P0] Удаление оценки двойным тапом в окне 500 мс
**Где:** `app/src/main/java/com/politex/ui/screens/GradesScreen.kt:105-118` (`DeleteArmState`, `DELETE_ARM_TIMEOUT_MS = 500L`), `:465-480` (`armedId`), `:631-655` (чип, `color = if (armed) ColorDangerFill`), обучение `:347` («Двойное нажатие по оценке удалит её»).
**Что видит/чувствует:** первое нажатие «взводит» оценку (заливка красным), второе в течение 0.5 с — удаляет. Для TalkBack это два отдельных активирования с паузой больше 0.5 с → удаление недоступно. Для человека с тремором двойной тап в 500 мс — лотерея. Обратная связь «взведено» передаётся **только цветом** (красная заливка), без текста/иконки — не видит дальтоник и не слышит незрячий (нет `stateDescription`).
**Нарушение:** Nielsen #5 (предотвращение ошибок) + #1 (видимость статуса); WCAG 2.2.1 Timing Adjustable, 2.5.1 Pointer Gestures, 1.4.1 Use of Color, 4.1.2.
**Фикс:** заменить механизм на явное «Удалить» (долгое нажатие / иконка корзины в чипе) с существующим undo (`:556-590` сохранён — это правильно); если механика остаётся — `stateDescription = "Нажмите ещё раз, чтобы удалить"`, иконка/текст в armed-состоянии, и увеличенное окно (≥2 с) с настраиваемым таймаутом.
**Проверка:** TalkBack удаляет оценку за одно действие; тест на `DeleteArmState` уже есть в юнит-тестах (`:105-118` — чистая функция, удобно расширить).

### [P1] Активная вкладка навигации в тёмной теме не читается (все 8 тем)
**Где:** `ui/screens/MainScreen.kt:273-277` (`selectedIconColor = selectedTextColor = ColorNavSelected`), `ui/theme/AppTheme.kt:182` (`navSelected = active` для тёмной палитры), `ui/theme/Color.kt:163`.
**Что видит/чувствует:** в тёмной теме подпись и иконка выбранной вкладки окрашиваются в «средний» акцент на почти чёрном фоне — 10sp-текст сливается. Замеры: COLLEGE 3.79, EMERALD 3.67, GRAPHITE 3.43, AMBER 3.69, STEEL 3.12, INDIGO 2.94, PLUM 2.89, BORDEAUX 2.69. Ни одна тема не проходит AA 4.5, пять из восьми не проходят даже 3:1. Пользователь не понимает, где он находится — особенно в «Другое», где вкладка ведёт на большой хаб.
**Нарушение:** WCAG 1.4.3 Contrast (minimum) AA; Nielsen #1 (видимость статуса системы).
**Фикс:** в `darkPaletteWithAccents` заменить `navSelected = active` на `navSelected = brand` (светлый вариант акцента): замерено для всех 8 тем — 5.66…7.36:1, проходит AA. Для COLLEGE: `#6FA3D8` = 6.97. Дополнительно усилить не только цветом: у выбранной вкладки уже есть `indicatorColor` — оставить, но поднять `selectedTextColor` до контрастного.
**Проверка:** юнит-тест «navSelected vs bgMain ≥ 4.5» по `AppTheme.entries.flatMap { listOf(it.palette, it.darkPalette) }`; скриншот dark для каждой темы.

### [P1] Бейджи типов заданий: мелкий текст и низкий контраст (светлая тема)
**Где:** `ui/screens/TasksScreen.kt:594-611` (текст 10sp на `badgeColor.copy(alpha = 0.12f)`), цвета `ui/theme/Color.kt:91-96`.
**Что видит/чувствует:** 10sp Bold — самый мелкий осмысленный текст в продукте (≈7.5dp капители), а контраст на 12 %-подложке в светлой теме не дотягивает: КУРСОВАЯ 2.48, ПРАКТИКА 3.25, ЛАБ 3.64, КОНТРОЛЬНАЯ 3.89, ДОМАШНЯЯ 4.13. Проходит только ДИПЛОМ (9.88). В тёмной теме всё в порядке (5.75–7.99). Итог: в светлой теме тип задания фактически не читается — а это первое, что студент ищет в списке.
**Нарушение:** WCAG 1.4.3 (нормальный текст < 18.66px bold) — все пары ниже 4.5.
**Фикс:** затемнить светлые бейдж-цвета (проверено на подложке): `badgeHW #0369A1` (4.98), `badgeLab #6D28D9` (5.82), `badgePract #0F766E` (4.64), `badgeExam #BE123C` (5.12); `badgeCourse` — уйти от оранжевого: `#C2410C` даёт 4.35 (мало), брать темнее (≈`#9A3412`) и перепроверить. Плюс поднять размер до 11sp и разрешить 2 строки.
**Проверка:** тест по парам `badge* → blend(badge,0.12,bgMain)`; скриншот `shot_tasks.png` в светлой теме.

### [P1] Компактное расписание: тач-таргеты преподавателя и кабинета ≈20–24dp
**Где:** `ui/screens/ScheduleScreen.kt:1450`, `:1515`, `:1714` — `.then(if (compact) Modifier else Modifier.heightIn(min = 44.dp))`.
**Что видит/чувствует:** в компактном режиме (а его включают как раз те, кому «всё крупное не влезает») строка «преподаватель · кабинет» — кликабельная — не получает минимальной высоты: её высота равна высоте текста ≈14sp → ≈20dp. Промах по преподавателю → открывается карточка другого человека или переход в карту вместо карточки. Плюс сам предмет обрезается до **одной** строки (`:1342 maxLines = if (compact) 1 else 2`) — «Архитектура аппаратных средств» превращается в «Архитектура ап…» без способа увидеть полное имя.
**Нарушение:** WCAG 2.5.8 Target Size (Minimum) 24×24 минимум, Android — 48×48dp; 1.4.4 Resize Text (при 2.0 обрезка усиливается).
**Фикс:** убрать условный `else Modifier` — минимальная высота нужна и в компакте (можно 40dp, но не меньше 24); обрезку субъекта оставить, но дать доступ к полному названию (тап по карточке → карточка урока/детали).
**Проверка:** Compose-тест: у узла с `testTag` строки преподавателя `assertHeightIsAtLeast(24.dp)` в compact=true.

### [P1] Дизайн-система: `Tokens.HitTarget = 44.dp`, чипы 40/32dp
**Где:** `ui/theme/Tokens.kt:8-18` (`HitTarget = 44.dp`, `IconHit = 44.dp`, `ChipScreen = 40.dp`, `ChipForm = 32.dp`; `ButtonText = 12.sp`, `ChipText = 11.sp`).
**Что видит/чувствует:** «единственно правильный» тач-таргет в проекте — 44dp, то есть на 4dp меньше платформенного минимума; токен используется в 30 местах (Settings 4, TeacherHome 4, Grades 3, College 3, Schedule 3, GroupSchedule 3, GroupSelection 3, …), плюс ~25 ручных `heightIn(min = 44.dp)` и один `32.dp` (`RoomScheduleDialog.kt:216`). Это корневая причина мелких целей: разработчик берёт токен и получает 44.
**Нарушение:** WCAG 2.5.5 (AAA) / 2.5.8 (AA, 24dp — формально ок), Android Material — 48×48dp; практическая доступность для 50+.
**Фикс:** одна правка токена: `HitTarget = 48.dp`, `IconHit = 48.dp`, `ChipScreen = 48.dp`; для `ChipForm` оставить 32 визуально, но обернуть `Modifier.minimumInteractiveComponentSize()` (Compose уже соблюдает 48dp-касание при меньшем визуале).
**Проверка:** grep `heightIn(min = 4[0-7]\.dp` → 0 совпадений; UI-тест на `minimumInteractiveComponentSize`.

### [P1] Технические тексты ошибок вместо человеческих
**Где:** `ui/screens/MaterialBaseScreen.kt:320` (`"Не удалось импортировать: ${it.message ?: it.javaClass.simpleName}"`), `:335` (то же для удаления), `ui/screens/SettingsScreen.kt:238` (`"Не удалось сохранить: ${e.message}"`), `:277, 283` (`"Не удалось прочитать файл: ${it.message}"`).
**Что видит/чувствует:** студент приносит PDF из деканата, импорт падает — и он читает «Не удалось импортировать: java.lang.IllegalStateException». Это не ошибка пользователя, но звучит как приговор; непонятно, что делать (пережать? открыть иначе? другой файл?). По контрасту с сильными текстами рядом («Конвертируйте файл в .docx (Word → «Сохранить как» → .docx) и загрузите заново», `MaterialCommon.kt:185`) — это регресс качества.
**Нарушение:** Nielsen #9 (помощь в распознавании и исправлении ошибок); WCAG 3.3.1 (идентификация ошибки), 3.3.3 (подсказка по исправлению).
**Фикс:** во всех четырёх местах — короткий человеческий текст + следующий шаг (см. «Рекомендации по текстам»), техническую деталь — в лог, а не на экран.
**Проверка:** grep по `it.javaClass.simpleName` / `${e.message}` в UI-строках → 0; скриншот экрана ошибки импорта.

### [P1] Нажатие не даёт обратной связи: `indication = null`
**Где:** `app/src/main/java/com/politex/ui/util/BouncyClick.kt:32-37` — единственная обёртка клика (`bouncyClickable`), ≈150 вызовов во всех экранах; `role` не задаётся нигде (`role =` встречается 0 раз вне `SettingsScreen`), `onClickLabel` — 0 раз.
**Что видит/чувствует:** вместо ripple — только масштабирование 0.95 за 120 мс. Для пользователя это выглядит как «кнопка не нажалась»: он жмёт второй раз, а на медленном устройстве получает двойное срабатывание (в оценках это вообще удаление, см. P0-3). Для TalkBack элемент объявляется без роли («двойное нажатие для активации», но не «кнопка»/«флажок»).
**Нарушение:** Nielsen #1 (видимость статуса) и #2 (соответствие системы реальному миру); WCAG 4.1.2 Name, Role, Value.
**Фикс:** вернуть `indication = ripple()` (или хотя бы alpha-оверлей), добавить параметры `role: Role? = null`, `onClickLabel: String? = null` и `Modifier.minimumInteractiveComponentSize()` внутри обёртки — три строки, которые чинят сразу ≈150 мест.
**Проверка:** `grep -c "indication = null"` → 0; TalkBack на карточке урока говорит «… кнопка».

### [P2] fontScale 2.0 клипует текст в фиксированных высотах
**Где:** `ui/screens/GradesScreen.kt:327-335` (`height(96.dp)` + `fontSize = 40.sp`), `:393` (`height(28.dp)` + text), `ui/screens/MainScreen.kt:229` (`heightIn(min = 72.dp)`) + `:266` (`fontSize = 10.sp`), `ui/screens/LessonsHubScreen.kt:105` (44dp) + `:122` (11sp), `CollegeScreen.kt:462` (8sp).
**Что видит/чувствует:** при системном шрифте «Крупный/Очень крупный» (это первое, что включает человек со слабым зрением) 40sp превращается в 80sp внутри 96dp — средний балл в обучении обрезается; подписи вкладок «Расписание/Уроки/Звонки/Другое» упираются в 72dp и усекаются до «Расписа…»; «Материалы/Задания/Оценки» на 44dp-вкладках — до «Матери…».
**Нарушение:** WCAG 1.4.4 Resize Text (текст должен масштабироваться до 200 % без потери контента), 1.4.10 Reflow.
**Фикс:** заменить фиксированные `height` на `heightIn(min = …)` там, где внутри текст (96 → `heightIn(min = 96.dp)`); для 40sp — авто-размер (`TextAutoSize`) или уменьшение при `fontScale > 1.3`; подписи вкладок — `maxLines = 2` вместо `softWrap = false`.
**Проверка:** Roborazzi-шоты при `fontScale = 2.0` для 5 экранов (расписание, уроки, оценки, звонки, настройки) — нет обрезанного текста.

### [P2] Расписание: шапка без группы/подгруппы и без статуса синхронизации
**Где:** `ui/components/MainHeaderBanner.kt:17-44` (только логотип, 56dp) — используется как `MainTopBar` (`MainTopBar.kt:7-9`); группа видна лишь в подзаголовке экрана (`ScheduleScreen.kt:540-550`) и то, что это группа, никак не помечено; подгруппа видна только в настройках (`SettingsScreen.kt:518-587`).
**Что видит/чувствует:** студент 2-й подгруппы смотрит «Расписание» и не может отличить свою пару от общей; чтобы проверить, «та ли подгруппа», нужно идти в «Другое → Настройки» через 3 экрана. Шапка при этом занята логотипом на 56dp + строка статус-бара.
**Нарушение:** Nielsen #1 (видимость состояния) и #6 (узнавание вместо припоминания).
**Фикс:** в шапку — «`Группа 2ИС-21 · 2 подгруппа`» и чип-переключатель подгруппы рядом с «СЕГОДНЯ/ЗАВТРА»; логотип уменьшить/убрать на скролле.
**Проверка:** пользовательский тест «определи, твоя ли это пара» без перехода в настройки.

### [P2] Системный back ведёт себя по-разному на соседних вкладках
**Где:** `ui/screens/MainScreen.kt:123-129` (`backAction`): `SCHEDULE, LESSONS, BELLS -> EXIT`, `COLLEGE -> TO_SCHEDULE`; `BackHandler` `:205-211`.
**Что видит/чувствует:** с «Уроков» и «Звонков» одно нажатие back **закрывает приложение** (даже если пользователь ушёл вглубь внутри хаба), а с «Другое» — мягко возвращает на расписание. Пользователь не может выучить правило: на одной вкладке back «назад», на другой «выход».
**Нарушение:** Nielsen #4 (согласованность и стандарты).
**Фикс:** единое правило: back всегда откатывает вкладку на «Расписание», и только с «Расписания» — выход (с тостом «Нажмите ещё раз, чтобы выйти»).
**Проверка:** UI-тест по 4 вкладкам: `Espresso.pressBack()` → ожидаемая вкладка.

### [P2] Настройки: 8 секций в одном полотне, вложенная панель на 11 строк
**Где:** `ui/screens/SettingsScreen.kt:293-431` — секции `ПРОФИЛЬ, РАСПИСАНИЕ, УВЕДОМЛЕНИЯ, ВНЕШНИЙ ВИД, КАРТА, ДАННЫЕ, ОБНОВЛЕНИЯ, О ПРИЛОЖЕНИИ` (8), 11 `SettingsRow` + 4 карточки-композита; `BellCountdownSection` (`:1063-1263`) раскрывается в 4 стиля + ~4 темы + 3 области = **11 строк внутри одной секции**; сворачиваемых секций — только одна.
**Что видит/чувствует:** чтобы дойти до «Внешний вид» (а это будущая фича тем), нужно проскроллить профиль, расписание с подгруппой, уведомления с раскрытой панелью звонков; экран ощущается «бесконечным». Заказчик просил убрать лишние описания — но проблема не в описаниях (их всего 6), а в **объёме**.
**Нарушение:** Nielsen #7 (гибкость: можно свернуть), #8 (минимализм: 8 секций на одном уровне).
**Фикс:** сгруппировать в 4: «Учёба (группа/подгруппа/компактность)», «Уведомления», «Внешний вид», «Данные и приложение»; «Звонки» и «Карта» — подстраницами со стрелкой; все секции сделать сворачиваемыми с запоминанием.
**Проверка:** «3 прокрутки»-тест: тема доступна максимум за 1 экран скролла.

### [P2] Терминология: «Уроки» / «Задания» / «урок» = разные вещи
**Где:** вкладка `AppTab.TASKS("Уроки")` (`ui/viewmodel/AppViewModel.kt`), внутри хаб «Материалы / Задания / Оценки» (`LessonsHubScreen.kt:43-49`), в расписании кнопка «Открыть задания» (`ScheduleScreen.kt:2103`), а «урок» в расписании = пара («1 УРОК», `BellsScreen.kt:641`).
**Что видит/чувствует:** новичок тапает «Уроки» в ожидании расписания уроков — попадает на задания; в расписании видит «Открыть задания» и не уверен, что это то же место; преподаватель в «Звонках» видит «1 УРОК» и «до звонка».
**Нарушение:** Nielsen #2 (язык пользователя) и #4 (согласованность).
**Фикс:** вкладку назвать «Учёба» (или «Задания», но не «Уроки»); «пара» — оставить для слота, «урок» — для занятия в звонках; в расписании «Открыть задания» → «Задания».
**Проверка:** словарь терминов в репозитории + грепом по строкам: одно понятие = одно слово.

### [P2] Сброс группы и выход из режима преподавателя без подтверждения
**Где:** `SettingsScreen.kt:405-421` («Сбросить группу» → `finishAffinity()` сразу), `:298-311` (`TeacherModeCard` → `onSwitchRole` мгновенно чистит `selected_group`, подгруппу и режим).
**Что видит/чувствует:** одно нажатие — и приложение закрывается, настройки группы/подгруппы/режима стёрты. Это необратимо и звучит как «оно сломалось»; на соседнем экране удаление одного задания требует и диалога, и undo.
**Нарушение:** Nielsen #5 (предотвращение ошибок) + непоследовательность защиты; WCAG 3.3.4 (обратимость/подтверждение для критичных действий).
**Фикс:** диалог «Сбросить группу? Вернётесь к выбору группы» + undo-тост; для смены роли — подтверждение с перечнем того, что сбросится.
**Проверка:** тест `reset_group_btn` → появляется `AlertDialog`.

### [P2] Карта: план этажа — единый узел семантики, комнаты недоступны с TalkBack
**Где:** `ui/screens/CollegeMapScreen.kt:953-1154` (`MapCanvas`, `contentDescription = "План этажа"`), обвод — `hitTestRoom` (`:734`), поиск — `SearchField` (`:831-905`).
**Что видит/чувствует:** кабинет на плане выбирается только тапом по Canvas; TalkBack видит один узел «План этажа». Альтернатива есть (ввод номера в поиск, «кабинет не найден» обрабатывается: `:869`), поэтому это не блокер, но маршрут «пальцем по плану» недоступен.
**Нарушение:** WCAG 1.1.1 (нет текстового эквивалента для визуальной информации), 2.1.1.
**Фикс:** список помещений этажа под планом (список уже почти есть — панель кабинета), либо `customActions` «Показать кабинет по номеру»; мелкие кабинеты — не меньше 24dp касания.
**Проверка:** TalkBack: добраться до кабинета 214 без Canvas.

### [P3] Дубли в семантике: иконка + подпись объявляют одно и то же
**Где:** `MainScreen.kt:250-254` (`Icon(contentDescription = tab.title)`) и `:257-260` (label `= tab.title`); `SettingsScreen.kt:1051-1058` (`contentDescription = label` вместо `stateDescription`); `TasksScreen.kt:803-811` (декоративная корзина с описанием «Удалить»).
**Что видит/чувствует:** TalkBack говорит «Расписание, Расписание, вкладка»; переключатель объявляет подпись, но не «включено/выключено».
**Нарушение:** WCAG 4.1.2 (избыточность/некорректная роль).
**Фикс:** у иконок вкладок `contentDescription = null`; у Switch — `Modifier.semantics { stateDescription = if (checked) "Включено" else "Отключено" }`; декоративную корзину — `null`.
**Проверка:** TalkBack-обход нижней навигации и настроек.

### [P3] Мелкий текст: 87 текстов на ≤11sp, из них 8sp и 9sp
**Где:** гистограмма `fontSize = N.sp` по `ui/**`: 8sp — 1 (`CollegeScreen.kt:462`), 9sp — 1, 10sp — 14, 11sp — 70, 12sp — 112; `EmptyState` note — 11sp (`ui/components/EmptyState.kt:81`), подписи вкладок — 10sp.
**Что видит/чувствует:** 8sp в бейдже админки («ADMIN») не читается даже на 6.5", 10–11sp подписи и сноски — на пределе для 45+ и на солнце.
**Нарушение:** WCAG 1.4.4, Android-рекомендация ≥12sp для body.
**Фикс:** минимум 12sp для body/подписей (11sp — только ALL-CAPS каптели), 8sp убрать полностью; бейдж админки — 10sp.
**Проверка:** правило в lint/тесте: `fontSize < 11.sp` допустим только с `@AllowedSmallText`.

### [P3] Нет режима «тёмная тема как в системе»
**Где:** `util/AppThemeStore.kt:40-49` (`setDark(context, dark: Boolean)`), `ui/theme/Theme.kt:16`; выключатель `SettingsScreen.kt:651-653`.
**Что видит/чувствует:** тема только бинарная и ручная; пользователь с авто-переключением по расписанию получает светлый экран ночью (и наоборот) — типичная жалоба «приложение слепит вечером».
**Нарушение:** Nielsen #6; WCAG 1.4.3 (косвенно), Android-стандарт `isSystemInDarkTheme`.
**Фикс:** три состояния: «Как в системе / Светлая / Тёмная», по умолчанию — как в системе.
**Проверка:** смена системной темы → приложение следует.

### [P3] Плейсхолдеры и микрокопия: «Группы X нет…» без следующего шага
**Где:** `GroupScheduleScreen.kt:296, 302, 833, 917`, `StudentsScreens.kt:396, 399, 602`, `CollegeScreen.kt:1904`.
**Что видит/чувствует:** «Группы 2ИС-99 нет в опубликованном расписании на 06.11.2026» — факт без действия; пользователь не понимает, опечатка это, или сайт не выложил.
**Нарушение:** Nielsen #9.
**Фикс:** добавить действие/подсказку (см. тексты ниже).
**Проверка:** пустой/ошибочный экран всегда содержит хотя бы одно действие.
